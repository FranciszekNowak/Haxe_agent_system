 Frozen block contract (the one shared reference)

 Input blocks (emitted by readers, ordered):
 { "type": "text",  "order": 0, "md": "..." }
 { "type": "image", "order": 1, "ref": "<clickup_url>", "mime": "image/png",
   "source": "input", "source_ref": "<attachment_id>", "alt": "..." }
 Output blocks (emitted by the drafting model):
 { "type": "text",  "md": "..." }
 { "type": "image", "mode": "embed_input", "ref": "<handle>", "caption": "...", "alt": "..." }
 { "type": "image", "mode": "generate",    "prompt": "...", "aspect": "1:1", "caption": "...", "alt": "..." }
 ref is always a URL or temp path — never raw bytes across a workflow boundary.

 Sequencing & gating

 - Blocks 1–7 (INPUT) need only Docling — no external image accounts. Build these first; they deliver
 standalone value (the agent reads attached specs/photos).
 - Blocks 8–12 (OUTPUT/GENERATION) are gated by Block 8 (image-provider provisioning). Block 1 and
 Block 8 are verify-then-act, which is how this plan self-resolves the open "is Docling up / are providers
 ready" questions — by doing them, not by deciding up front.
 - Each block names a test surface (default: a ClickUp task in Lista testy AI, e.g. 869dhad2q, with the
 relevant sample fixtures attached). Two adjacent input blocks can share one window if you want fewer /clears.

 Verification philosophy (every block)

 Per CLAUDE.md Definition of Done: trigger the real ClickUp flow (or the n8n manual trigger), inspect every
 node (not just a green run), and check the Alerts task 869dj2z2c — any WARN/CRITICAL during a test is a
 failure until explained. Claude attempts verification autonomously before handing any part back to you.

 Silent-failure coverage rolled up across blocks

 - Extraction failure → [BRAK…] + WARN, run continues (B2/B3).
 - Image on Bedrock / PD path → WARN + visible Polish substitute, never a silent drop (B6).
 - Image tier degrade / total gen failure → WARN + [Obraz niedostępny], comment still posts (B9/B11).
 - Provider credit/availability cliff → caught at the provisioning gate (B8) + per-call WARNs.
 - Orphaned attachments on post failure → rollback + retained temp; crashed-run temp → TTL sweep (B10).
 - Every model/image call cost-logged in one place (Log Model Run), summed without double-count (B9/B12).
